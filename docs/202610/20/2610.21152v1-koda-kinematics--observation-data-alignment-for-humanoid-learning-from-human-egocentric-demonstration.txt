Training humanoid whole-body vision–language–action (VLA) policies requires costly robot demonstra-
tions with aligned robot-view observations and controller-compatible whole-body state–action labels.
Egocentric human demonstrations offer scalable supervision but have misaligned views and sparse
motion cues. Existing approaches either pretrain policies that still require robot data for adaptation
or generate controller-specific commands that limit reuse. Conversion also requires robot-view obser-
vations aligned with the generated whole-body motion. We present KODA (Kinematics–Observation
Data Alignment), which converts egocentric RGB demonstrations into whole-body VLA training data
using a reusable canonical trajectory to guide robot-view synthesis and generate controller-specific
whole-body state–action supervision. KODA first generates a simulator-checked whole-body trajectory
using a sparse tracker with sampling-based command optimization. This generated trajectory directly
determines the onboard camera poses used to synthesize corresponding robot-view observations. The
motion, observations, and task instruction form a canonical record. For each deployment controller,
KODA optimizes commands to track the stored motion and records the corresponding action labels
and proprioceptive states. When switching controllers, KODA retains this canonical record and
regenerates whole-body state–action supervision for co-training with matching robot demonstrations.
We evaluate KODA on four Unitree G1 loco-manipulation tasks using two whole-body controllers,
SONIC and HEFT. With robot data held fixed, macro-average success on conditions covered by human
demonstrations but absent from robot data improves by 45.0 and 46.25 percentage points, respectively.
Under both controllers, this metric shows an upward trend across the evaluated human-data budgets,
suggesting potential for further scaling.

Introduction
Humanoid robots combine locomotion and dexterous manipulation in a versatile platform for operating in
environments designed for people. Realizing this potential requires policies that coordinate body posture,
mobility, and bimanual manipulation across the whole body. Whole-body vision–language–action (VLA)
models aim to learn such coordination from onboard observations and task instructions (Jiang et al., 2026; Hu
et al., 2026). Training requires corresponding robot observations, whole-body states, and action supervision
compatible with the deployment whole-body controller (WBC) interface. Collecting these demonstrations on
the target humanoid is costly, limiting coverage across tasks, objects, and environments.
Human demonstration interfaces and egocentric datasets provide RGB images, camera poses, and sparse
bilateral hand-position references at scale (Chi et al., 2024; Hoque et al., 2026; Punamiya et al., 2026).

Their success on fixed-base arms (Chi et al., 2024) and in dexterous manipulation (Zheng et al., 2026b;
Liu et al., 2026b) motivates extending human-data supervision to whole-body VLAs. Approaches such as
EgoVLA, WholeBodyVLA, and MotionWAM learn human-derived priors for humanoid policies but still
depend on target-humanoid demonstrations for adaptation (Yang et al., 2025b; Jiang et al., 2026; Zheng
et al., 2026a). Target-humanoid data collection therefore remains a bottleneck. Other work converts human
demonstrations into robot-oriented supervision. EgoHumanoid uses whole-body human measurements and a
shared end-effector-and-navigation action space for co-training (Shi et al., 2026). HALOMI trains policies
on human demonstrations using head–hand command labels tied to a dedicated controller (Zhao et al.,
2026). These methods produce supervision tied to particular action interfaces, creating data silos that
limit reuse across whole-body controllers; their outputs do not directly provide the whole-body states and
compatible actions needed for other WBC interfaces. Their converted episodes also require observations
corresponding to the generated robot motion. Fixed-offset reprojection (Shi et al., 2026) shifts the human
camera without following the generated robot trajectory, leaving this observation–motion correspondence
unresolved. Moreover, retaining only controller-tuned commands limits reuse to that controller’s command
space and tracking behavior. A reusable record must support adaptation to different deployment controllers.
We target a distinct data-conversion setting: augmenting an existing controller-specific humanoid whole-body
dataset from egocentric RGB, camera poses, and hand references. This setting requires three capabilities: (i)
generating simulator-checked whole-body trajectories from sparse human references; (ii) synthesizing onboard
observations aligned with the generated robot motion; and (iii) instantiating the same converted record as
compatible state–action supervision for different deployment controllers.
To address these three challenges, we present KODA (Kinematics–Observation Data Alignment), a framework

Our contributions are: (a) A data-conversion framework that constructs whole-body robot motion and
corresponding onboard observations from egocentric human demonstrations. (b) A canonical representation and
controller-specific control command generation procedure for generating compatible state–action supervision
from the same converted records across deployment interfaces. (c) Real-world evidence of the training value
and scaling potential of converted human demonstrations on four G1 loco-manipulation tasks. With 50 robot
demonstrations per task fixed, adding 100 converted human demonstrations per task increases macro-average
success by 45.0 and 46.25 percentage points under SONIC and HEFT, respectively, on object conditions
covered by human training clips but absent from robot demonstrations. This metric shows an upward trend
across the evaluated data budgets under both interfaces.

Related Work
2.1
Humanoid Loco-Manipulation
Humanoid data collection methods use direct teleoperation, human imitation, or whole-body tracking to
obtain robot demonstrations. OmniH2O, HOMIE, HumanPlus, and TWIST2 provide interfaces for whole-
3


body teleoperation or imitation learning (He et al., 2024; Ben et al., 2025; Fu et al., 2024; Ze et al., 2025).
OmniRetarget preserves human–object and human–environment interactions during retargeting, while SONIC
tracks whole-body motion for physically grounded control (Yang et al., 2025a; Luo et al., 2026; Xie et al., 2025;
Han et al., 2026). WholeBodyVLA learns loco-manipulation from vision and instructions, while OpenHLM
and MotionWAM study whole-body humanoid policy and action-model training (Jiang et al., 2026; Hu et al.,
2026; Zheng et al., 2026a; Xie et al., 2026b). These approaches establish the control and learning foundation
for humanoid loco-manipulation, but their supervision is collected or represented in a target-robot interface.
2.2
Egocentric Data and Cross-Embodiment Alignment
Egocentric interfaces and datasets provide a scalable source of visual and motion supervision. UMI records
robot-compatible gripper trajectories and images, while EgoDex and EgoVerse provide large-scale RGB data
with camera and hand-motion annotations (Chi et al., 2024; Hoque et al., 2026; Punamiya et al., 2026). Ψ0
and EgoVLA use human data for embodied pretraining, and EMMA, EgoEngine, and Ego2Robot combine
human video with robot learning or robot-data synthesis (Wei et al., 2026; Yang et al., 2025b; Zhu et al., 2026;
Liu et al., 2026b; Wang et al., 2026). Related cross-embodiment methods address appearance and viewpoint
transfer through cross-painting or robot-view augmentation (Chen et al., 2024a,b).
For humanoids, EgoHumanoid uses whole-body measurements, fixed-offset view alignment, and training-time
perturbations (Shi et al., 2026). HALOMI adopts this view alignment and reference adaptation based on
the cross-entropy method (CEM) for a dedicated controller (Zhao et al., 2026). KODA also uses command
optimization, but derives onboard views from generated whole-body motion. Its canonical motion–observation
records can be reused to augment manipulation datasets for compatible WBCs through controller-specific
command generation and state recording.
3
System Framework
KODA converts egocentric human episodes into robot-view observations, canonical whole-body motion, and
controller-compatible state–action data for VLA training as shown in Fig. 2. The conversion has three stages:
Whole-Body Motion Generation in Sec. 3.2 produces a simulator-checked trajectory from sparse human
references; Robot Onboard View Generation in Sec. 3.3 uses the corresponding body–camera trajectory to
synthesize aligned observations, forming a controller-independent canonical record; and Control Command
Generation in Sec. 3.4 tracks this motion with the selected controller to derive its state–action supervision. The
canonical motion and observations are reused across interfaces, while controller-specific states and commands
enable co-training with matching real-robot demonstrations. Qualitative demonstration timelines are provided
in Appendix E.

Contact-Aware Hand Retargeting
HAWOR (Zhang et al., 2025) estimates world-space MANO hand poses
from egocentric RGB. Following AnyTeleop (Qin et al., 2023), KODA retargets them to obtain initial robot
wrist poses and active finger-joint values using MANO palm geometry and a calibrated wrist-to-palm transform;
distal mimic joints follow a fixed coupling map (Qin et al., 2023). Contact-aware refinement then adjusts this
initialization on reliable contact frames. To identify these frames, EfficientSAM3 (Zeng et al., 2025) segments
hand/forearm pixels, while nearby valid non-hand depths provide object-surface samples. Reliable contact
frames are identified from multi-finger proximity, depth, and local surface consistency, then temporally filtered;
without reliable contact, the initialization is retained.
At contact frames, wrist and finger poses are refined to preserve hand–object geometry. Following OmniRetar-
get (Yang et al., 2025a), selected human landmarks and corresponding robot-hand points are paired with
the same nearby object samples to form connected world-frame interaction meshes. Each vertex descriptor
is its offset from the uniformly weighted mean of its neighbors. We optimize wrist poses and finger joints
to minimize differences between corresponding human and robot descriptors, preserving the demonstrated
hand–object geometry. During optimization, object samples remain fixed, robot points are recomputed by
forward kinematics, wrist translations, local rotations, and finger corrections are bounded, and deviations from
initialization are penalized. Corrections are interpolated between contact frames and held constant outside
their range. The optimized bilateral-wrist and finger trajectories are denoted by wret
1:T and f ret
1:T , respectively;
the tracking stage uses Ch

3.4
Control Command Generation and VLA Training
Given ecan
R , KODA generates controller-specific command sequences for SONIC (Luo et al., 2026) and
HEFT (Liu et al., 2026a) on the Unitree G1 with BrainCo hands. Our command generation is related to
test-time command optimization (Xie et al., 2026a), which searches for controller-specific input commands
through closed-loop simulation to improve motion tracking. At 50 Hz, SCO optimizes a shared pelvis-pose
and 29-body-joint residual space (hands excluded) against fixed qR
1:T . The G1 reference contains world-frame
pelvis position and quaternion, 29 body-joint positions and velocities, and world-frame link poses from forward
kinematics. Each candidate is decoded by the selected controller and rolled out in simulation with the same
cost for both controllers—joint-position MSE, 14-link pose error, reference deformation, PD-target change,
and terminal tracking penalties—and the same Control Command Generation settings reported in Sec. 4.1.

4
Evaluation
We evaluate whether KODA improves real-robot task success by augmenting fixed robot datasets with human
demonstrations, reusing the same canonical records across SONIC and HEFT. EgoHumanoid (Shi et al.,
2026) and HALOMI (Zhao et al., 2026) use different control interfaces and do not directly provide compatible
whole-body state–action data. SONIC ablations assess the training benefits of observation alignment and
controller-specific supervision; tracking diagnostics characterize motion fidelity and controller realization.
4.1
Experimental Setup
Platform, data, and evaluation. We use a Unitree G1 with BrainCo dexterous hands on four whole-body tasks:
cup-to-basket, parcel-to-shelf, basket-to-shelf, and cup-to-drawer. Each task has 50 real-robot demonstrations
from the corresponding SONIC or HEFT PICO teleoperation pipeline and 100 human egocentric demonstrations
captured with a chest-mounted iPhone using MobileEgo Anywhere (Palanisamy et al., 2026). All 400 human
clips include iPhone-recorded depth. Both sources use 50 Hz. The scaling study evaluates SONIC (Luo et al.,
2026) and HEFT (Liu et al., 2026a); component ablations use SONIC with 50 robot and 100 converted-human
demonstrations per task. Per controller configuration, GR00T N1.7 (Bjorck et al., 2025) trains on all four tasks
for 20,000 iterations with batch size 160. Within each task, robot/human sampling is proportional to episode
counts; other sampling settings follow GR00T defaults. We report one training run per configuration and 20
8


real-robot trials per task and condition. This trial count matches EgoHumanoid’s 20 trials per setting (Shi
et al., 2026) and exceeds the 10 trials per task and model reported in Ψ0 (Wei et al., 2026). Success requires
completing the placement without a fall or unrecovered manipulation failure. Reported averages weight the
four tasks equally.
Conditions covered by human demonstrations. Robot-ID uses object appearance and pose conditions present
in the robot demonstrations. Robot-OOD uses conditions absent from those demonstrations: a green bottle is
replaced by a brown bottle in cup-to-basket and cup-to-drawer, a purple parcel by a white parcel in parcel-
to-shelf, and the basket handle is tilted by approximately 30◦in basket-to-shelf. The human training pool
contains 80 shifted and 20 robot-matched clips per task. Robot-OOD tests whether human demonstrations
supply coverage missing from the robot dataset, rather than zero-shot generalization to conditions absent
from all training data. Data and evaluation details are in Appendices D.1 and D.2.
CEM settings. Both stages run at 50 Hz and use CEM with 80 candidates per iteration, 8 iterations per replan,
and a 40-step horizon. Whole-Body Motion Generation uses 10 elites and executes 10 steps before replanning.
Control Command Generation with SONIC and HEFT uses 9 elites and executes 20 steps before replanning.
4.2
Extending Robot Demonstration Coverage
Each task combines 50 fixed robot demonstrations with 0, 25, 50, 75, or 100 converted human demonstrations,
randomly sampled independently at each budget from its 100-clip pool without nesting. Policy architecture,
training budget, and evaluation protocol remain fixed. TABLE 1 shows that KODA provides its largest gains
on conditions missing from robot demonstrations. With 100 converted demonstrations, SONIC Robot-OOD
success rises from 3.75% to 48.75% (+45 percentage points), and HEFT rises from 5.00% to 51.25% (+46.25
points). Robot-ID success also improves, from 62.5% to 72.5% for SONIC and from 68.75% to 76.25% for
HEFT. Robot-OOD macro-average trends upward over tested budgets for both controllers. Individual-task and
Robot-ID results vary at intermediate data sizes, so we focus on overall gains at the full data budget. KODA
thus supplies useful supervision for additional conditions covered by human demonstrations without adding
robot demonstrations. Fig. 4 illustrates converted data and real-robot execution in the Robot-OOD setting
for cup-to-drawer. See Appendix F for the other three tasks. The same converted human demonstrations
yield large Robot-OOD gains under both SONIC and HEFT, demonstrating cross-controller reuse, as shown
in TABLE 1. The following ablations isolate observation alignment and control command generation.
4.3
Observation Alignment
We hold the converted demonstrations, state–action supervision, policy architecture, training budget, and
evaluation protocol fixed across four tasks. No alignment retains the original human images. Fixed offset uses
a 0.10 m vertical camera shift with ±0.05 m training-time perturbations, adapting the fixed-offset strategy
of (Shi et al., 2026) to chest-mounted capture. Fixed offset and Motion-based reprojection use only reprojection
and hole inpainting; Motion-based reprojection derives the target camera poses from the canonical robot
motion. Full alignment additionally removes human arms and renders and composites the target robot. See
Appendix D.3 for details.
Full alignment reaches 48.75% Robot-OOD success versus 23.75% with the adapted EgoHumanoid fixed-
offset baseline (Shi et al., 2026) and 18.75% without alignment (TABLE 2). Motion-based reprojection
reaches 37.5%. Fixed offset, Motion-based reprojection, and Full alignment yield Robot-ID point estimates of
63.75%/66.25%/72.5%, respectively.
4.4
Controller-Consistent State–Action Supervision
The variant without SCO directly uses the generated canonical whole-body motion as the tracking controller’s
reference, omitting optimization during control command generation while retaining Whole-Body Motion
Generation and Robot Onboard View Generation. Both variants use identical canonical trajectories, observa-
tions, demonstrations, policy architecture, training budget, and evaluation protocol. Since body states come
from controller rollouts, the comparison evaluates state–action supervision as a whole. See Appendix D.3 for
details.

5
Limitations
KODA does not yet fully reproduce fine-grained hand–object interactions, limiting their fidelity and physical
feasibility. In the future, we plan to incorporate real-to-sim scene reconstruction and contact modeling
to better recover object geometry and interaction dynamics. We will also broaden human data sources
beyond egocentric recordings, including third-person videos and motion capture, converting diverse human
demonstrations into canonical whole-body records for controller-specific state–action generation and policy
training.
6
Conclusion
KODA converts egocentric human demonstrations into canonical whole-body motion and onboard observations,
then generates controller-specific state–action supervision for VLA training. Reusing these records with fixed
robot data improves VLA task success under SONIC and HEFT on four G1 tasks, especially on conditions
covered only by human demonstrations. Reduced tracking errors and co-training gains despite residual
mismatch support expanding robot-policy coverage.

A.1
Contact-aware hand retargeting
Initialization and contact evidence.
HAWOR (Zhang et al., 2025) supplies world-space MANO hand estimates.
Retargeting following AnyTeleop (Qin et al., 2023) uses palm geometry and a calibrated wrist-to-palm transform
to initialize each robot wrist and its active finger joints. Distal mimic joints are determined by the coupling
map, so they are not independent optimization variables. A correspondence between selected human landmarks
and robot-hand points provides the geometric basis for refinement. The correspondences express analogous
locations on the two hands; they do not require their shapes or articulation ranges to coincide.
The hand/forearm segmentation removes human-hand pixels from the depth samples used as object evidence.
Nearby valid non-hand depths provide local object surface points. Multi-finger proximity, depth validity,
and local surface consistency identify candidate contact frames, which are temporally filtered. These checks
determine where geometric refinement is supported by the observation. When an entire sequence has no
reliable contact, the initialized hand trajectory is retained. Contact evidence is used to recover spatial
hand–object relationships; it is not a measurement of contact force.
Local wrist and finger corrections.
At one contact frame, let (p0, R0) be the initialized wrist pose and f 0
the active finger-joint vector for one hand. In the implemented six-active-joint hand model, δp, δω ∈R3 and
δf ∈R6. We optimize ξ = (δp, δω, δf) ∈R12 using
p(ξ) = p0 + R0δp,
R(ξ) = R0 Exp([δω]×),
f(ξ) = clip(f 0 + δf, fmin, fmax).
(A.1)
The initialized position p0 is in the world frame, and R0 maps wrist coordinates to world coordinates. Both
wrist corrections are expressed relative to the initialized wrist frame. Translations are in meters; rotation
vectors and finger-joint angles are in radians. The clip is componentwise, and fmin, fmax ∈R6 are the
active-joint limits in the robot’s MJCF model. Here [δω]× is the skew-symmetric matrix associated with
the rotation vector, and Exp maps it to a valid rotation. Forward kinematics evaluates the robot landmarks
under the corrected wrist and finger configuration, including the fixed mimic-joint relationships. Thus wrist
placement and finger articulation affect the same geometric objective.
Shared interaction geometry.
Let P h be the selected human landmarks, P R(ξ) their robot counterparts, and
O the object samples for this frame. Following the interaction-mesh construction of OmniRetarget (Yang
et al., 2025a), the ordered vertex arrays V h = [P h; O] and V R(ξ) = [P R(ξ); O] share vertex correspondences
and connectivity. The implementation constructs adjacency from a Delaunay tetrahedralization of the human
landmarks and object samples, with a nearest- neighbor fallback when tetrahedralization fails. Connectivity
is then held fixed throughout the frame’s optimization and reused for the robot vertices.

SCO reduces sparse-reference error through the controller’s dynamics,
but its realized wrists can still deviate from the retargeted manipulation reference. Temporal Mink IK (Zakka,
2024) addresses this residual by adjusting the arm chain, including the wrists. The optimized floating base,
torso, and lower-body trajectory are held fixed, and the contact-aware finger trajectory is retained. Joint
limits, per-step displacement and velocity bounds, and self-collision constraints restrict the arm updates. A
posture penalty discourages unnecessary departures from the SCO configuration. Temporal restrictions are
applied across successive refined states so that reducing a frame’s wrist error does not permit an unconstrained
joint jump.
The final configuration combines the refined arms, retargeted fingers, and fixed non-arm motion. It supplies
both the canonical motion reference and the body trajectory used for robot-view rendering. Holding the
non-arm configuration fixed preserves those kinematic tracks; changes to the arms can still affect the response
of a whole-body controller. The replay comparison in Sec. 4.5 therefore evaluates trackability before and after
refinement. These measurements assess the demonstrated trajectories under the evaluated controller, without
assuming that inverse kinematics alone establishes dynamic feasibility for arbitrary motions or deployment
interfaces.

C.4
Hand Targets and Recorded State
Both body-action formats append 12 BrainCo hand-joint targets, six per hand, yielding 76-dimensional SONIC
actions and 50-dimensional HEFT actions. The hand command is constructed from the retargeted robot hand

for each hand to distinguish grasp from release. For grasp, the command uses the calibrated BrainCo grasp
pose to encourage active closure. For release, it uses the current retargeted joint angles. These targets are
delivered separately to hand control. This construction specifies the closure command without interpreting a
retargeted geometric pose as a measured grasp force.

C.5
Episode Export and Observation Reuse
The procedure below summarizes the conversion from a canonical episode to controller-specific supervision.
Controller-specific episode export
1. Read the canonical motion, synthesized images, retargeted hand trajectory, and instruction on their
common temporal index.
2. For each receding-horizon window, decode CEM residuals into candidate body references, encode
them for controller κ, simulate, and evaluate Eq. C.4 against the fixed canonical target.
3. Retain the selected prefix of up to 20 steps, shortened when fewer steps remain, and continue from
its resulting simulated state. Collect the optimized reference and realized body motion.
4. Record the selected reference as SONIC tokens or HEFT body labels; append the 12 grasp/release
hand targets.

Experimental Protocol and Metric Definitions
This appendix specifies the data composition, controlled comparisons, and interpretation of the evaluation
metrics used in Sec. 4.1. The task-success results remain in TABLES 1–3; the motion and rollout errors
remain in TABLE 4.
D.1
Demonstration Sources and Evaluation Conditions
The experimental platform is a Unitree G1 with BrainCo dexterous hands. For each task and deployment
controller, the robot dataset contains 50 demonstrations collected through the corresponding SONIC or
HEFT PICO teleoperation pipeline. The human pool contains 100 demonstrations per task, recorded with a
chest-mounted iPhone using MobileEgo Anywhere (Palanisamy et al., 2026). All 400 human clips include
phone-recorded depth, and both demonstration sources use 50 Hz sequences. The same human canonical
records supply the motion, synthesized observations, and instructions for both controllers; command generation
and state recording produce the controller-specific training fields.
TABLE D.1 specifies the task goals and condition changes. Robot-ID is defined relative to object appearance
and pose conditions in the robot demonstrations. Robot-OOD changes these conditions beyond that robot
dataset. Each task’s human pool contains 80 shifted and 20 robot-matched clips, so the shifted test conditions
are represented in the human training pool. This evaluates whether converted human data supplies coverage
absent from the robot demonstrations. It does not test conditions excluded from both training sources. The
80:20 composition describes the complete human pool; the independently sampled smaller budgets are not
specified as having that same proportion.
D.2
Training Budgets and Success-Rate Aggregation
For each controller configuration, GR00T N1.7 (Bjorck et al., 2025) is trained jointly on all four tasks for
20,000 iterations with batch size 160. Within each task, robot and converted-human sources are sampled in
proportion to their episode counts; other sampling settings follow GR00T defaults.
The scaling study combines 50 fixed robot demonstrations with 0, 25, 50, 75, or 100 converted-human
demonstrations per task. Human subsets are sampled randomly and independently at each budget without
27


nesting. Policy architecture and training budget remain fixed. All component ablations use SONIC with 50
robot and 100 converted-human demonstrations per task.
Each configuration is trained once and evaluated in 20 real-robot trials per task under each of the Robot-ID
and Robot-OOD conditions. A trial succeeds when the placement is completed without a fall or unrecovered
manipulation failure. We report the percentage of successful trials for each task and the unweighted mean
across the four tasks, separately for each condition.
